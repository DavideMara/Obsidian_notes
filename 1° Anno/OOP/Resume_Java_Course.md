## 1. INTRODUCTION

The main reasons why **Object Oriented Programming (OOP)** is effective are:
1. **Increased productivity**
2. **Making the programmer's work easier**
3. **Speeding up development**
4. **Reducing errors**

### Structured Programming vs. OOP
* **Structured Programming (e.g., C)**: A problem is divided into simpler subproblems, which in turn are divided into subprograms, such as functions and procedures (*top-down* approach).
* **OOP (e.g., Java)**: An application is built by assembling and interacting simpler **objects**. Objects are designed using **classes**, built, and finally used. To design an object, you specify:
  * **Properties** (attributes or fields)
  * **Functionalities** (methods or functions)

> [!NOTE]
> ### The Three Pillars of OOP
> 1. **Inheritance**: The ability to reuse an existing design and modify it for one's own needs.
> 2. **Encapsulation**: Code reuse, abstraction, and error containment.
> 3. **Polymorphism**: The ability of an object to behave differently depending on the context and value.

## 2. THE JAVA LANGUAGE

The Java environment includes both a **compiler** and an **interpreter** (Java Runtime Environment, **JRE**).

```text
[Java Source Code] 
       │
       ▼ (Compiler)
[Java Bytecode] (platform-independent)
       │
       ├─► (JRE Interpreter - Windows) ──► Execution
       ├─► (JRE Interpreter - Linux)   ──► Execution
       └─► (JRE Interpreter - macOS)   ──► Execution
```

* **Bytecode**: Platform-independent pseudo-instructions generated by the compiler.
* **Interpreter (JVM)**: Translates the bytecode into an executable specific to the operating system. This guarantees an excellent combination of **speed** and **portability**.

## 3. OBJECT ORIENTED PROGRAMMING IN JAVA

* **Class**: The generic model or "template" for a set of objects with similar characteristics.
* **Object**: The particular instance (concrete element) of a class.
* **Attributes (Properties/Fields)**: Describe the state, appearance, and qualities of the object. There are instance fields and class fields (`static`).
* **Methods (Behaviors)**: Functions defined inside a class that operate on objects and manipulate their properties. In Java, *no* functions can be defined outside of a class.

### Creating an Object
```java
Motocicletta m;              // 1. DECLARATION: Create the reference variable 'm' (occupies 4 bytes in memory)
m = new Motocicletta();      // 2. INSTANTIATION: Physically allocate and create the new motorcycle
m.marca = "Guzzi 1000";      // 3. INITIALIZATION: Assign properties to the variable
m.colore = "rossa";          
m.mostra();                  // 4. INVOCATION: Call the method on the object
```

### Constructors
A constructor is a special method that:
1. Instantiates the object and returns its memory address.
2. Initializes the state of the object (assigning initial values to properties from parameters).

```java
// Constructor Definition
public Motocicletta(String marca, String colore, boolean a) {
    this.marca = marca; 
    this.colore = colore; 
    this.accesa = a; 
}

// Declaration, instantiation, and initialization on a single line
Motocicletta m = new Motocicletta("Guzzi 1000", "rossa", false);
```

### Memory Management
The Java runtime memory is divided into three main areas:

| Memory Area | Description |
| :--- | :--- |
| **STACK** | Space where methods are executed. Contains parameters and local variables. The `main` method with `args[]` is always present. The spaces for non-static methods remain only until their execution is completed. |
| **HEAP** | Dynamic space where the actual objects reside along with their properties. |
| **STATIC** | Space where static variables reside, which are globally accessible. |

> [!IMPORTANT]
> **References and Addresses**: When an object variable is declared, it stores a hexadecimal address (a pointer to the allocated area in the Heap). Initially, it is `null`. With `new`, space is allocated in the Heap and the address is stored in the variable.
> Deallocation of objects that are no longer referenced occurs automatically thanks to the **Garbage Collector**.

### Compiler vs. Interpreter
* **Compiler (Static Checks)**: Based on variable declarations; it checks syntactic correctness and whether variables are initialized before use.
* **Interpreter (Dynamic Runtime Checks)**: Detects errors during execution, such as:
  * Using an unconstructed object (`NullPointerException`).
  * Accessing an out-of-bounds array index (`ArrayIndexOutOfBoundsException`).
  * Parsing non-numeric strings (`NumberFormatException`).
  * Casting between incompatible classes (`ClassCastException`).

---

### a. Inheritance, Interfaces, and Packages
* **Inheritance (`extends`)**: Allows defining a subclass that inherits fields and methods from a superclass. Private fields are inherited but are not directly accessible.
  * **Single Inheritance**: In Java, each class can only extend one superclass to ensure simplicity and safety for the compiler, preventing structural ambiguity.
* **Design Approaches**:
  * *Bottom-up*: More complex classes are built starting from simpler ones.
  * *Top-down*: Classes are organized in a tree structure, starting from general/abstract superclasses down to specific subclasses.

* **Interfaces (`interface` / `implements`)**: Collections of method declarations that allow classes located in different branches of the hierarchy to share similar behaviors. A class can implement **multiple interfaces**. An interface can contain:
  1. Abstract instance method signatures (without a body).
  2. Static constants.
  3. Implemented `default` methods (overridable).
  4. Implemented static methods (non-overridable).

* **Package**: Group related classes and interfaces together to avoid name conflicts. By default, only `java.lang` is imported; other classes require an `import` directive or their fully qualified name.

---

### b. Data Polymorphism
An object of a subclass can be assigned to a variable of the superclass type. Similarly, an interface-type variable can reference objects of any class that implements that interface.

```java
Lavoratore l3 = new Operaio(); // Operaio inherits from Lavoratore
l3.stipendio();                // Executes the overridden method in Operaio
```

> [!TIP]
> * **Early Binding (Compiler)**: Statically checks that the invoked method is declared in the variable's class (`Lavoratore`).
> * **Late Binding (Interpreter)**: Determines the actual type of the object at runtime (`Operaio`) and executes its specific method. Java always uses late binding except for static, final, or private methods.

---

### c. Typecasting
Allows explicitly informing the compiler of the actual type of the referenced object to unlock access to specific methods not present in the superclass. If the type is incompatible at runtime, a `ClassCastException` is thrown.
```java
Operaio o = (Operaio) l3; // Explicit typecast
```

---

### d. Arrays
An array is an object that collects homogeneous elements of the same type.
* **Explicit Creation**: `int[] arr = new int[10];`
* **Implicit Creation**: `int[] arr = {1, 2, 3, 4};`
* It has a read-only public field `length` indicating its size.

## 4. OBJECT MANIPULATION

### Assigning Values to Objects
A reference can be valued via:
1. Calling a constructor (`new`).
2. Assigning `null`.
3. Assigning a non-null constant value.
4. Assigning the return value of a compatible method.
5. Assigning the reference of another object (sharing the same memory location).

### Constants (`final`)
The `final` keyword prevents subsequent modification of the value.
* **final Variable**: Cannot be reassigned.
* **final Class**: Cannot be extended (e.g., `String`).
* **final Method**: Cannot be overridden in subclasses.

### Class Members (`static`)
* **Static Fields**: Unique global variables for the class, shared by all instances and usable even without instantiating the class.
* **Static Methods**: Methods invokable directly on the class (`ClassName.method()`). They cannot access non-static (instance) fields and methods of the class, and they do not support polymorphism.

### Comparing Objects
* **Operator `==` / `!=`**: Compares whether the variables contain the **same memory address** (if they point to the same object).
* **`equals()` Method**: Checks the equality of the **content** of the object (must be overridden, e.g., for Strings).

### Encapsulation
Hides the internal parts and implementation details of an object, allowing access and usage only through the public interface defined by the programmer.

#### Visibility Modifiers:
* `public`: Accessible anywhere.
* `protected`: Accessible within the package and in subclasses (even outside the package).
* *default* (no modifier): Accessible only within the package.
* `private`: Accessible only within the same class.

#### Objectives of Encapsulation:
1. **Data Protection**: Setter methods validate input parameters.
2. **Information Hiding**: Internal details are hidden from the outside.
3. **Abstraction**: Ability to change the internal implementation without affecting the client code.
4. **Error Containment**: Prevents unwanted side effects outside the methods.

### The `this` Keyword
Represents the reference to the current object. Used within instance methods and constructors to resolve name ambiguity or to pass the object itself as an argument.

### Parameter Passing
In Java, parameters are **always passed by value** (a local copy is created).
* *Primitive types*: The variable itself is copied (changes remain local).
* *Objects*: The variable containing the address is copied. Therefore, you cannot change the object that the external reference points to, but you can modify the fields of the referenced object.

### Overloading
The ability to define multiple methods within the same class with the same name but with **different signatures** (different number or types of parameters).

### Abstract Classes and Methods
* **Abstract Class (`abstract`)**: Cannot be instantiated; serves as a base for subclasses.
* **Abstract Method**: Declared without a body. Forces concrete subclasses to provide an implementation.

## 5. COMPLEXITY

**Computational complexity** evaluates the resources needed to execute an algorithm as a function of the input size ($n$).

### Evaluation of $n$:
* **Integers**: Number of digits of the integer ($v \leftrightarrow \text{number of digits} = \log_b v$).
* **Arrays**: Length of the array.
* **Lists**: Length of the list.
* **Trees**: Number of nodes.

### Analyzed Resources:
1. **Time**: Operations performed to complete the processing.
2. **Space**: Allocated memory, including Stack frames for recursion.

### Asymptotic Notations:
* **$O(f(n))$** (Big-O): Asymptotic upper bound. Represents the behavior in the worst-case scenario ($g(n) \le c \cdot f(n)$).
* **$\Omega(f(n))$** (Omega): Asymptotic lower bound. Represents the best-case scenario ($g(n) \ge c \cdot f(n)$).
* **$\Theta(f(n))$** (Theta): Asymptotic tight bound ($c_1 \cdot f(n) \le g(n) \le c_2 \cdot f(n)$).

### Computational Cost: Iteration vs. Recursion
* **Iteration**:
  * *Time*: Number of cycles $\times$ cost of each cycle.
  * *Space*: $O(1)$ (constant).
* **Recursion**:
  * *Time*: Total number of recursive calls.
  * *Space*: $O(\text{recursion depth})$ (each call adds a frame to the Stack).

## 6. RECURSION

Recursion consists of solving a problem by calling the function itself on smaller-sized data.

> [!IMPORTANT]
> ### Rules for Correct Recursion
> 1. Presence of at least one **base case** solved directly (without recursion).
> 2. Recursive steps that reduce the input to converge towards the base case.
> 3. A parameter that tracks the current size or position.

### Classification of Time Complexity:
1. **Logarithmic ($O(\log n)$)**: Searching in a sorted vector.
2. **Linear ($O(n)$)**: Summing elements, calculating factorials.
3. **Polynomial ($O(n^k)$)**: Matrix multiplication.
4. **Exponential ($O(2^n)$)**: Towers of Hanoi.

### Algorithms and Code Examples

#### 1. Factorial with Tail Recursion
Optimizes Stack usage by passing the partial result as a parameter.
```java
private static long factRC(int n, long ris) {
    if (n == 0) return ris;
    else return factRC(n - 1, ris * n);
}
public static long factRC(int n) { 
    return factRC(n, 1); 
}
```

#### 2. Fibonacci Sequence (Standard Recursive)
```java
static long fiboR(int n) {
    if (n <= 2) return 1;
    else return fiboR(n - 1) + fiboR(n - 2);
}
```
* **Time Complexity**: $O(2^n)$ (exponential, due to redundant calculations).
* **Space Complexity**: $O(n)$ (maximum Stack depth).

#### 3. Fast Exponentiation
```java
public static double potenzaR2(double b, long e) {
    if (e == 0) return 1;
    else if (e % 2 == 0) return potenzaR2(b * b, e / 2);
    else return b * potenzaR2(b * b, e / 2);
}
```
* **Time/Space Complexity**: $\Theta(\log e)$.

#### 4. Binary Search (Sorted Array)
* **Recursive Version**:
```java
public class Vettore {
    int[] dati;
    
    public int ricercaBinRic(int x) { 
        return ricercaBinRic(dati, x, 0, dati.length - 1);
    }
    
    private static int ricercaBinRic(int[] dati, int x, int inizio, int fine) {
        if (inizio > fine) return -1;
        int centro = (inizio + fine) / 2;
        int c = dati[centro];
        if (c == x) return centro;
        else if (x < c) return ricercaBinRic(dati, x, inizio, centro - 1);
        else return ricercaBinRic(dati, x, centro + 1, fine);
    }
}
```
* **Iterative Version**:
```java
public static int ricercaBinIter(int dati[], int x) {
    int inizio = 0, fine = dati.length - 1;
    while (inizio <= fine) {
        int centro = (inizio + fine) / 2;
        int c = dati[centro];
        if (c == x) return centro;
        else if (x < c) fine = centro - 1;
        else inizio = centro + 1;
    }
    return -1;
}
```
* *Complexity Comparison*:
  * Recursive: Time $O(\log N)$, Space $O(\log N)$.
  * Iterative: Time $O(\log N)$, Space $O(1)$ (preferred in real-world scenarios).

#### 5. Quicksort
An algorithm based on the *Divide and Conquer* technique.
```java
static int partition(int[] array, int inizio, int fine) {
    int pivot = array[fine];
    int i = inizio - 1;
    for (int j = inizio; j < fine; j++) {
        if (array[j] <= pivot) {
            i++;
            int temp = array[i];
            array[i] = array[j];
            array[j] = temp;
        }
    }
    int temp = array[i + 1];
    array[i + 1] = array[fine];
    array[fine] = temp;
    return i + 1;
}

private static void quicksort(int v[], int inizio, int fine) {
    if (inizio < fine) {
        int mid = partition(v, inizio, fine);
        quicksort(v, inizio, mid - 1);
        quicksort(v, mid + 1, fine);
    }
}
```
* **Time Complexity**:
  * Best case: $\Theta(N \log N)$ (balanced partitioning).
  * Worst case: $O(N^2)$ (sorted or inversely sorted array with pivot chosen at an extremity).
* **Iterative Quicksort**: Can be implemented by explicitly simulating the recursive call stack using a Stack data structure (LIFO logic) to hold the remaining `[inizio, fine]` intervals to be processed.

#### 6. Towers of Hanoi
```java
private void hanoi(int N, String S, String I, String D) {
    if (N == 1) trasferisci(1, S, D);
    else {
        hanoi(N - 1, S, D, I); // Move N-1 discs to the intermediate peg
        trasferisci(N, S, D);   // Move disc N to the destination peg
        hanoi(N - 1, I, S, D); // Move N-1 discs from intermediate to destination
    }
}
```
* **Time Complexity**: $O(2^N)$ (exactly $2^N - 1$ moves).
* **Space Complexity**: $O(N)$ (maximum Stack depth).

#### 7. Bubblesort
```java
static public void ordina(int vettore[]) {
    int temp;
    for (int i = 0; i < vettore.length - 1; i++) {
        for (int j = vettore.length - 1; j > i; j--) {
            if (vettore[j] < vettore[j - 1]) {
                temp = vettore[j];
                vettore[j] = vettore[j - 1];
                vettore[j - 1] = temp;
            }
        }
    }
}
```
* **Time Complexity**: $O(N^2)$ in all cases.
* **Space Complexity**: $O(1)$ (in-place sorting).

## 7. EXCEPTIONS

An **exception** is an anomalous event that occurs during program execution. All exception classes inherit from `Throwable`.

```text
                  Throwable
                 /         \
            Error           Exception
                           /         \
           RuntimeException           Checked Exceptions
         (Unchecked Exceptions)      (IOException, etc.)
```

* **`Error`**: Serious and unrecoverable system problems (e.g., `OutOfMemoryError`). The application should not try to catch them.
* **`Exception`**: Catchable anomalous conditions:
  1. **Unchecked Exceptions**: Derive from `RuntimeException`. Detected at runtime. There is no requirement to catch or declare them (e.g., `NullPointerException`, `ClassCastException`, `IndexOutOfBoundsException`, `NumberFormatException`).
  2. **Checked Exceptions**: All other exceptions. The compiler forces you to handle them with a `try-catch` block or declare them in the signature with `throws` (e.g., `IOException`, `FileNotFoundException`).

### Exception Handling (`try-catch-finally`)
```java
try {
    // Code that might throw exceptions
} catch (FileNotFoundException e) {
    // Catch and process specific exception
} catch (IOException e) {
    // Catch and process a generic I/O exception
} finally {
    // Executed in any case (useful for closing files or connections)
}
```
> [!WARNING]
> The `catch` blocks must be ordered from the most specific to the most generic type. If you put `catch(Exception)` before `catch(IOException)`, the subsequent code will not compile (unreachable catch block error).

### Declaring Exceptions (`throws`)
Allows delegating exception handling to the calling method.
```java
public void leggiFile(String nomefile) throws IOException { }
```
* **Override**: An overridden method in a subclass can declare fewer checked exceptions than the original method in the superclass, but never more.

### Creating and Throwing Exceptions (`throw`)
```java
// Defining a custom checked exception
public class SunSpotException extends Exception {
    public SunSpotException() { }
    public SunSpotException(String msg) { super(msg); }
}

// Throwing the exception
if (connessionePersa) {
    throw new SunSpotException("Error: connection disrupted");
}
```

## 8. INPUT AND OUTPUT STREAMS

**I/O Streams** allow the transfer of data between a source and a destination. The reference classes belong to the `java.io` package.

### Types of Streams

| Stream Type | Description | Base Classes | Concrete Examples |
| :--- | :--- | :--- | :--- |
| **Byte Streams** | For handling generic binary data (images, audio, serialized objects). | `InputStream`<br>`OutputStream` | `FileInputStream` / `FileOutputStream`<br>`BufferedInputStream` / `BufferedOutputStream`<br>`DataInputStream` / `DataOutputStream`<br>`ObjectInputStream` / `ObjectOutputStream` |
| **Character Streams** | For handling text data (txt files, logs, configurations). | `Reader`<br>`Writer` | `FileReader` / `FileWriter`<br>`BufferedReader` / `BufferedWriter`<br>`InputStreamReader` / `OutputStreamWriter`<br>`PrintWriter`<br>`Scanner` |

### Closing Streams and Resource Management
All streams must be closed after use to prevent system resource leaks.
Since Java 7, it is recommended to use the **try-with-resources** statement for automatic resource closing on objects that implement `AutoCloseable`:

```java
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
    String riga;
    while ((riga = br.readLine()) != null) {
        int n = Integer.parseInt(riga);
        // Processing...
    }
} catch (IOException e) {
    System.out.println("I/O Error: " + e.getMessage());
} catch (NumberFormatException e) {
    System.out.println("Invalid number format: " + e.getMessage());
}
```

## 9. MULTITHREADING

### Core Concepts
* **Process**: An instance of a running program with private memory space.
* **Thread**: A lightweight concurrent execution path inside a process. Shares memory with other threads of the same process.

### Creating Threads

#### Method 1: Extending the `Thread` class
```java
public class MioThread extends Thread {
    @Override
    public void run() {
        // Instructions executed in the parallel thread
    }
}
// Starting
MioThread t = new MioThread();
t.start(); // Creates the new stack and asynchronously executes run()
```

#### Method 2: Implementing `Runnable`
Recommended to bypass the single inheritance limitation.
```java
public class MiaAttivita implements Runnable {
    @Override
    public void run() {
        // Instructions
    }
}
// Starting
Thread t = new Thread(new MiaAttivita());
t.start();
```

### Main Control Methods
* `t.start()`: Starts the thread.
* `yield()`: Temporarily yields the CPU to threads of equal priority.
* `t.join()`: Suspends the calling thread until thread `t` completes execution.
* `Thread.sleep(millis)`: Suspends the current thread for a specified time.
* *Deprecated methods* (unsafe): `suspend()`, `resume()`, `stop()`.

### Synchronization
When multiple threads modify a shared resource concurrently, inconsistent states (*race conditions*) can occur.
* **Thread-safe**: Code designed to be executed concurrently by multiple threads without conflicts.
* **`synchronized`**: Guarantees exclusive access (mutual exclusion) to a method or a block of code for only one thread at a time by acquiring a **lock** on the object.
  * If a thread tries to access a `synchronized` method already locked by another thread, it is suspended waiting for the lock to be released.
  * Improper use can lead to performance bottlenecks or permanent stalls (**deadlocks**).

### Communication between Threads (`wait` and `notify`)
Methods invokable inside synchronized contexts:
* `wait()`: Releases the object lock and suspends the current thread until another thread calls `notify()`.
* `notify()`: Wakes up a single thread waiting on the object's lock.
* `notifyAll()`: Wakes up all threads waiting on the object's lock.

## 10. NETWORK PROGRAMMING

### Sockets
A **Socket** is a software abstraction representing an endpoint of communication for sending and receiving data over the network.
* **IP Address**: Identifies the host on the network.
* **Port**: Integer representing the process on the destination machine to which the packet is delivered.
* **Client/Server Model**:
  * *Server*: Listens passively on a specific port.
  * *Client*: Actively initiates the connection by specifying the IP and port.

### SocketStream (TCP)
Provides a reliable, stable, connection-oriented, and bidirectional connection.
* **ServerSocket**: Used by the Server to accept incoming connections.
  * `accept()` method: Blocking wait for a client. Returns a `Socket` to exchange data.
* **Socket**: Used by the Client to connect or by the Server to communicate. Provides two streams:
  * `getInputStream()`: To receive bytes.
  * `getOutputStream()`: To send bytes.

### Client/Server Implementation Model

#### Server Code:
```java
ServerSocket ss = new ServerSocket(indirizzo);
while (true) {
    try {
        Socket s = ss.accept(); // Accept client connection (blocking)
        ThreadServer ts = new ThreadServer(s); // Handle in a separate thread
        ts.start();
    } catch (IOException e) {
        // Handle I/O errors
    }
}
```

#### Client Code:
```java
String server = (args.length == 1) ? args[0] : "localhost";
try (Socket socket = new Socket(server, porta)) {
    // Channel established, ready for communication
} catch (IOException e) {
    // Handle connection error
}
```

#### Data Exchange Modes
Native socket I/O streams are wrapped according to the needs:

```java
// 1. Send numbers (Client)
DataOutputStream out = new DataOutputStream(socket.getOutputStream());
out.writeInt(valore);
out.flush();

// 2. Receive numbers (Server)
DataInputStream in = new DataInputStream(socket.getInputStream());
int valore = in.readInt();

// 3. Send text (Client/Server)
PrintWriter out = new PrintWriter(socket.getOutputStream(), true); // autoflush active
out.println("Text message");

// 4. Receive text (Client/Server)
BufferedReader in = new BufferedReader(new InputStreamReader(socket.getInputStream()));
String riga = in.readLine();
```

> [!IMPORTANT]
> ### Data Synchronization in Multi-thread Server
> When multiple parallel threads on the Server modify the same set of shared data:
> 1. Create a dedicated class for storing the shared data.
> 2. Declare the class fields as `private`.
> 3. Make all read and write methods `public synchronized`.
> 4. Instantiate only one object of this class and pass it as a parameter to the constructors of each `ThreadServer` upon instantiation.
