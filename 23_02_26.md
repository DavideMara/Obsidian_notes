# Rappresentazione degli Alberi e Algoritmi su Alberi Binari di Ricerca

🎯 Summary
> [!abstract]  
> Questa lezione introduce la rappresentazione di alberi radicati (binari e generali con la tecnica left‑child right‑sibling) e le operazioni fondamentali sugli [[Binary Search Tree|Alberi Binari di Ricerca]]: visita simmetrica, ricerca, minimo, massimo, successore, predecessore, inserimento e cancellazione. Tutte le operazioni hanno complessità $O(h)$, dove $h$ è l'altezza dell'albero.

## Rappresentazione di alberi radicati

- Le liste concatenate sono efficienti per relazioni lineari, ma non per relazioni gerarchiche.
- Per alberi binari ogni nodo `x` contiene gli attributi:
  - `x.key` : valore (chiave)
  - `x.p` : puntatore al padre (NIL per la radice)
  - `x.left` : puntatore al figlio sinistro (NIL se assente)
  - `x.right` : puntatore al figlio destro (NIL se assente)
- La radice dell'intero albero `T` è accessibile tramite `T.root`; se `T.root == NIL` l'albero è vuoto.

> [!note] Estensione ad alberi con numero di figli limitato  
> Se ogni nodo ha al più `k` figli (costante), si possono usare puntatori `child1, child2, …, childk`. Questo schema però spreca memoria se `k` è grande e la maggior parte dei nodi ha pochi figli, e non funziona per numero di figli illimitato.

### Left‑child, right‑sibling representation
- Per alberi con numero arbitrario di figli si usa una rappresentazione compatta $O(n)$:
  - `x.left-child` : puntatore al primo figlio (il più a sinistra)
  - `x.right-sibling` : puntatore al fratello immediatamente a destra
- Se un nodo non ha figli, `left-child = NIL`; se è l'ultimo fratello, `right-sibling = NIL`.
- Il puntatore al padre `p` è mantenuto (opzionale, ma utile).

## Proprietà degli Alberi Binari di Ricerca (BST)

> [!cite] Proprietà fondamentale  
> Sia `x` un nodo in un BST:
> - Se `y` è nella sinistra di `x`, allora `y.key ≤ x.key`
> - Se `y` è nella destra di `x`, allora `y.key ≥ x.key`

- La visita **inorder** (simmetrica) stampa le chiavi in ordine non decrescente.
- La procedura `INORDER-TREE-WALK(x)`:
  ```cpp
  INORDER-TREE-WALK(x)
      if x != NIL
          INORDER-TREE-WALK(x.left)
          print x.key
          INORDER-TREE-WALK(x.right)
  ```

### Analisi del tempo di visita
> [!important] Teorema  
> Se `x` è la radice di un sottoalbero con `n` nodi, `INORDER-TREE-WALK(x)` costa $\Theta(n)$.

**Dimostrazione** (metodo di sostituzione):  
Sia $T(n)$ il tempo per visitare un sottoalbero di `n` nodi. $T(0)=c$.  
Per $n>0$, con `k` nodi nel sottoalbero sinistro e `n‑k‑1` nel destro:
$$ T(n) \le T(k) + T(n-k-1) + d $$
Si dimostra per induzione che $T(n) \le (c+d)n + c$, quindi $T(n)=O(n)$. Essendo anche $\Omega(n)$ (si visitano tutti i nodi), si ha $\Theta(n)$.

## Operazioni di interrogazione (query)

Tutte le seguenti operazioni costano $O(h)$ su un BST di altezza $h$.

### Ricerca (TREE‑SEARCH)
```cpp
TREE-SEARCH(x, k)
    if x == NIL or k == x.key
        return x
    if k < x.key
        return TREE-SEARCH(x.left, k)
    else
        return TREE-SEARCH(x.right, k)
```
Versione iterativa (più efficiente) segue lo stesso principio.

### Minimo e Massimo
```cpp
TREE-MINIMUM(x)
    while x.left != NIL
        x = x.left
    return x

TREE-MAXIMUM(x)
    while x.right != NIL
        x = x.right
    return x
```

### Successore e Predecessore
- **Successore** di `x`: nodo con chiave minima tra quelle maggiori di `x.key` (in termini di visita inorder, è il prossimo nodo visitato dopo `x`).
- Due casi:
  1. Se `x.right != NIL` → successore = minimo del sottoalbero destro (`TREE-MINIMUM(x.right)`)
  2. Altrimenti si risale verso l'alto finché non si trova un antenato di cui `x` è nel sottoalbero sinistro.
```cpp
TREE-SUCCESSOR(x)
    if x.right != NIL
        return TREE-MINIMUM(x.right)
    y = x.p
    while y != NIL and x == y.right
        x = y
        y = y.p
    return y
```
- Simmetrico per il predecessore.

## Operazioni di modifica

### Inserimento (TREE‑INSERT)
```cpp
TREE-INSERT(T, z)
    y = NIL
    x = T.root
    while x != NIL
        y = x
        if z.key < x.key
            x = x.left
        else
            x = x.right
    z.p = y
    if y == NIL
        T.root = z          // albero vuoto
    else if z.key < y.key
        y.left = z
    else
        y.right = z
```

### Cancellazione (TREE‑DELETE)
La cancellazione è più complessa e si articola in tre casi principali (quattro nella trattazione con `TRANSPLANT`).

#### Procedura ausiliaria TRANSPLANT
Sostituisce il sottoalbero radicato in `u` con quello radicato in `v`.
```cpp
TRANSPLANT(T, u, v)
    if u.p == NIL
        T.root = v
    else if u == u.p.left
        u.p.left = v
    else
        u.p.right = v
    if v != NIL
        v.p = u.p
```

#### Cancellazione di un nodo `z`
```cpp
TREE-DELETE(T, z)
    // caso 1: nessun figlio sinistro (include nessun figlio)
    if z.left == NIL
        TRANSPLANT(T, z, z.right)
    // caso 2: nessun figlio destro (ma ha figlio sinistro)
    else if z.right == NIL
        TRANSPLANT(T, z, z.left)
    // caso 3: due figli
    else
        y = TREE-MINIMUM(z.right)   // successore di z
        if y.p != z                 // y non è il figlio destro diretto
            TRANSPLANT(T, y, y.right)
            y.right = z.right
            y.right.p = y
        TRANSPLANT(T, z, y)
        y.left = z.left
        y.left.p = y
```

> [!example] Spiegazione dei casi  
> 1. **Nessun figlio sinistro** → rimpiazza `z` con il suo figlio destro (che può essere NIL).  
> 2. **Nessun figlio destro (ma ha sinistro)** → rimpiazza `z` con il figlio sinistro.  
> 3. **Due figli**:
>    - Si trova il successore `y` (minimo del sottoalbero destro). `y` non ha figlio sinistro.
>    - Se `y` è il figlio destro diretto di `z`, si rimpiazza `z` con `y` e si assegna il vecchio sinistro di `z` a `y.left`.
>    - Altrimenti, si sostituisce prima `y` con il suo figlio destro, poi si rimpiazza `z` con `y`, attaccando il vecchio destro di `z` come nuovo destro di `y` e il vecchio sinistro di `z` come nuovo sinistro di `y`.

> [!important] Complessità  
> Tutte le operazioni di inserimento e cancellazione richiedono $O(h)$ tempo su un albero di altezza $h$.
